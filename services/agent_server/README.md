# Agent Server

FastAPI 后端，提供管理员与普通用户的 Bearer 密钥认证。PydanticAI 采用精简依赖，暂未配置模型或聊天功能。本次只提供 API，没有独立管理页面，可通过 FastAPI `/docs` 调试接口。

## 配置与启动

| 环境变量                 | 说明                                                                    |
| ------------------------ | ----------------------------------------------------------------------- |
| `AGENT_SERVER_ADMIN_KEY` | 必填，高熵随机管理员密钥，长度为 32～4096 个可打印 ASCII 字符，不含空白 |
| `AGENT_SERVER_DB_PATH`   | 可选，SQLite 文件路径；默认服务目录 `data/users.db`                     |

部署时通过部署平台的密钥管理功能注入管理员密钥，不写进源码、普通配置或日志。管理员密钥缺失/过短、数据库不可用时，服务启动失败。

在本目录执行以下命令。本机开发可生成临时管理员密钥，命令不会将密钥显示到终端；需要使用同一管理员身份时应复用原值：

```sh
uv sync
export AGENT_SERVER_ADMIN_KEY="$(uv run python -c 'import secrets; print(secrets.token_urlsafe(32))')"
uv run uvicorn main:app --reload
```

服务默认监听 `127.0.0.1:8000`，只有回环连接允许 HTTP 开发。对外部署必须通过 HTTPS；使用 TLS 反向代理时，仅信任该代理的转发头。SQLite 文件需挂载持久卷并按用户数据保护、备份；默认数据目录已加入 Git 忽略规则。

认证使用请求头 `Authorization: Bearer <key>`，不接受 URL 查询参数或请求体中的密钥。没有额外 JWT、Cookie 或刷新令牌。客户端“登录”即验证密钥并使用平台安全存储保存，退出时清除本地密钥。当前客户端尚未接入这些操作。

## API

| 方法   | 路径                         | 权限             | 行为                                                                   |
| ------ | ---------------------------- | ---------------- | ---------------------------------------------------------------------- |
| GET    | `/health`                    | 匿名             | 返回 `{"status":"ok"}`                                                 |
| GET    | `/auth/me`                   | 管理员或普通用户 | 返回 `role` 和 `user_id`；管理员的用户 ID 为 null                      |
| POST   | `/admin/users`               | 管理员           | 请求 `{"name":"用户名称"}`，返回新用户及一次性显示的 `key`，状态码 201 |
| GET    | `/admin/users`               | 管理员           | 列出 `user_id`、`name`、`created_at`、`active`，不返回密钥或哈希       |
| POST   | `/admin/users/{user_id}/key` | 管理员           | 重置密钥并仅在本次响应返回新 `key`，旧密钥立即失效                     |
| DELETE | `/admin/users/{user_id}/key` | 管理员           | 撤销密钥，返回 204，保留用户身份和数据                                 |

用户名称去除首尾空白后需为 1～80 字符，仅用于标识用户，不参与认证。不同用户可同名，身份以服务端生成的 `user_id` 为准。

普通密钥由安全随机数生成，数据库仅存 SHA-256 哈希。用户 ID 与密钥分开，轮换不改变用户 ID、名称和创建时间。撤销后可重新生成密钥以恢复访问。更新部署管理员密钥并重启，可轮换管理员凭据，不影响普通用户。

所有认证和管理响应都设置 `Cache-Control: no-store`。密钥缺失/错误/已撤销返回 401，并带 Bearer challenge；普通用户访问管理接口返回 403；不存在的用户返回 404。认证不能通过时无匿名降级。

每次请求都重新验证密钥，轮换后新请求立即拒绝旧密钥；已开始的请求不会自动中断。后续聊天记录、配置等必须绑定认证所得的 `user_id`，当前尚未实现这些数据接口及流式连接。

```sh
uv run pytest
uv run ruff check .
uv run ruff format --check .
```

测试使用临时数据库和随机密钥，无需提前配置管理员密钥，不进行外部模型调用。
